# Architecture — SuntCastigator MVP

Single Next.js (App Router, TypeScript) app on Vercel + Supabase (Postgres/RLS, Auth magic link, Storage). No separate backend service — the PDF's "Node.js/FastAPI + PostgreSQL" requirement is satisfied by Next.js route handlers + Supabase Postgres.

## Requirement → mechanism map

| PDF requirement | Mechanism |
|---|---|
| Magic-link auth, 7-day session, multi-user brands (owner/editor) | Supabase Auth (email OTP/magic link); `brand_users` membership table with `role`; middleware guards `(dashboard)` routes |
| Campaign CRUD, draft until wizard completes | `campaigns` table, `status='draft'` default; wizard steps are server actions updating the draft; "Lansează" flips to `active` after validation |
| Eligible products, CSV upload, ILIKE search | `products` + `campaign_products` m2m; CSV parsed hand-rolled in a server action (no papaparse); Postgres `ILIKE` search |
| Code format → regex per campaign | Pure function `buildCodeRegex(length, charset)` in `/lib/code-format.ts` (unit-tested); regex string stored on the campaign |
| Prizes, >600 lei taxable, configurable tax rate | `prize_tiers` table; threshold + rate live in `settings` table; tax computed in `/lib/prize-tax.ts` |
| Rules PDF upload (S3-compatible) | Supabase Storage bucket `regulamente` (public-read, server-side upload only); R2 swap possible later |
| Public entry page, no login, one screen | `/c/[slug]` server component; campaign fetched server-side (service client, safe fields only) |
| Entry validation: format, duplicate, active window | Postgres function `submit_entry()` (SECURITY DEFINER) — atomic: regex check, duplicate check, window check, rate check, insert with status |
| Rate limiting per IP/phone — no Redis | DB-based inside `submit_entry()`: `count(*)` on `code_entries` per `(campaign_id, ip)` last hour and `(campaign_id, contact)` last 24h, backed by covering indexes. Fine at MVP volumes (thousands/campaign); revisit only if a campaign exceeds ~10 entries/sec |
| Auditable winner draw (recorded seed) | Seeded PRNG in TypeScript (mulberry32) + Fisher–Yates over a deterministic snapshot (entries ordered by `id`); `draws` row stores seed, participant count, SHA-256 of ordered entry ids, who ran it, when. Same seed + same snapshot ⇒ same winners, replayable in disputes |
| Dashboard stats + chart + CSV export | Aggregate queries via Supabase server client; chart with shadcn/ui charts (recharts); CSV streamed from a route handler, hand-rolled serializer |

## Public insert path — decision

`code_entries` has **no anon RLS policies**. The consumer page posts to `POST /api/entries` (route handler), which calls the `submit_entry` RPC with the **service-role** client. Rationale: validation (regex, duplicate, rate limit) must be server-authoritative and atomic; an anon-key INSERT policy would let bots bypass the checks entirely. The service key never leaves the server (CONVENTIONS.md).

## Schema (DDL sketch — finalized in T0.4)

```sql
create table brands (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  slug text not null unique,
  logo_url text,
  created_at timestamptz not null default now()
);

create table brand_users (
  brand_id uuid not null references brands(id) on delete cascade,
  user_id uuid not null references auth.users(id) on delete cascade,
  role text not null check (role in ('owner','editor')),
  created_at timestamptz not null default now(),
  primary key (brand_id, user_id)
);

create table products (
  id uuid primary key default gen_random_uuid(),
  brand_id uuid not null references brands(id) on delete cascade,
  sku text not null,
  name text not null,
  unique (brand_id, sku)
);

create table campaigns (
  id uuid primary key default gen_random_uuid(),
  brand_id uuid not null references brands(id) on delete cascade,
  name text not null,
  slug text not null unique,                -- public URL /c/[slug]
  status text not null default 'draft' check (status in ('draft','active','ended')),
  starts_at date,
  ends_at date,
  code_length int check (code_length between 6 and 14),
  code_charset text check (code_charset in ('letters','digits','alphanumeric')),
  code_regex text,                          -- generated by /lib/code-format.ts
  single_use_codes boolean not null default true,
  block_invalid_format boolean not null default true,
  limit_per_contact_24h int,                -- null = off
  rules_pdf_path text,                      -- Supabase Storage path
  hero_image_url text,
  how_to_text text,
  created_by uuid references auth.users(id),
  created_at timestamptz not null default now()
);

create table campaign_products (
  campaign_id uuid not null references campaigns(id) on delete cascade,
  product_id uuid not null references products(id) on delete cascade,
  primary key (campaign_id, product_id)
);

create table prize_tiers (
  id uuid primary key default gen_random_uuid(),
  campaign_id uuid not null references campaigns(id) on delete cascade,
  name text not null,
  quantity int,                             -- null = unlimited (instant)
  value_lei numeric(10,2) not null,
  kind text not null check (kind in ('instant','draw')),
  taxable boolean not null default false,   -- set by app from settings threshold
  sort_order int not null default 0
);

create table code_entries (
  id uuid primary key default gen_random_uuid(),
  campaign_id uuid not null references campaigns(id) on delete cascade,
  code text not null,
  full_name text not null,
  contact text not null,                    -- phone or email
  ip inet,
  status text not null check (status in ('valid','duplicate','invalid')),
  gdpr_consent_at timestamptz not null,
  created_at timestamptz not null default now()
);
create unique index uq_code_entries_valid on code_entries(campaign_id, code) where status = 'valid';
create index ix_code_entries_ip on code_entries(campaign_id, ip, created_at);
create index ix_code_entries_contact on code_entries(campaign_id, contact, created_at);
create index ix_code_entries_campaign_time on code_entries(campaign_id, created_at);

create table draws (
  id uuid primary key default gen_random_uuid(),
  campaign_id uuid not null references campaigns(id),
  prize_tier_id uuid not null references prize_tiers(id),
  seed text not null,
  participant_count int not null,
  participants_hash text not null,          -- sha256 of ordered entry ids
  ran_by uuid not null references auth.users(id),
  ran_at timestamptz not null default now()
);

create table winners (
  draw_id uuid not null references draws(id) on delete cascade,
  entry_id uuid not null references code_entries(id),
  position int not null,
  primary key (draw_id, position)
);

create table settings (
  key text primary key,
  value jsonb not null
);
-- seed rows: prize_tax_threshold_lei=600, prize_tax_rate=0.10 (validate with accountant),
--            entry_rate_limit_per_ip_hour=20
```

**RLS outline (T0.4, strong model only):** helper `is_brand_member(b uuid)` checking `brand_users` against `auth.uid()`. Every table: RLS ON. Brand members SELECT rows of their brand (via `brand_id` or the parent campaign's `brand_id`); INSERT/UPDATE for members on brand-owned tables; `code_entries`/`draws`/`winners` INSERT only via SECURITY DEFINER functions (no direct anon or member insert); `settings` readable server-side only. No self-signup: brands and memberships are seeded by the operator.

## Route map

| Route | Type | Auth |
|---|---|---|
| `/` | (marketing) landing | public |
| `/c/[slug]` | consumer entry page | public |
| `/login`, `/auth/callback` | magic link flow | public |
| `/dashboard` → `/dashboard/campaigns` | campaign list | brand member |
| `/dashboard/campaigns/new` | 4-step wizard (server actions per step) | brand member |
| `/dashboard/campaigns/[id]` | stats overview | brand member |
| `/dashboard/campaigns/[id]/entries` | entries table | brand member |
| `/dashboard/campaigns/[id]/draw` | winner extraction | brand member |
| `POST /api/entries` | public entry submission (rate-limited) | public |
| `GET /api/campaigns/[id]/export` | CSV eligible participants | brand member |
| `POST /api/campaigns/[id]/draw` | run draw (calls draw engine) | brand member (owner) |
| `GET /api/health` | db connectivity check | public |

Dashboard mutations use **server actions** (Next idiom, less boilerplate for weak agents); public submission, CSV and draw are **route handlers** (need explicit status codes 201/400/429 per the PDF).

## Dependency policy

Allowed: next, react, tailwindcss, shadcn/ui (+ its transitive radix/recharts), @supabase/supabase-js, @supabase/ssr, zod. Anything else: stop and ask (CLAUDE.md golden rule).
